# WinAPI 슈팅 게임 시스템 기획서

## 1. 문서 개요

- 프로젝트명(가칭): **비상하는 강철의 환상**
- 장르: 세로 스크롤 아케이드 슈팅(STG)
- 플랫폼: Windows / WinAPI
- 개발 기간: 4주(1개월)
- 목표: 1945 스타일의 전투기 슈팅을 기반으로, 명확한 탄막 규칙과 보스 페이즈 전투를 갖춘 3스테이지 완성형 데모 제작

본 문서는 이미 구현된 Unity풍 기반 구조(SceneManager, Component, Map 등)를 활용한다는 전제에서 작성한다. 한 달 안에 **플레이 가능한 완성도**를 확보하는 것이 최우선이며, 새 시스템은 재사용성과 디버깅 편의성을 기준으로 최소화한다.

---

## 2. 핵심 게임 루프

```text
타이틀
  → 스테이지 선택/시작
  → 일반 웨이브 전투
  → 중간보스(선택)
  → 보스 페이즈 전투
  → 결과 화면
  → 다음 스테이지 또는 엔딩
```

플레이어는 적을 격파해 점수 및 아이템을 얻고, 강화된 공격으로 다음 웨이브와 보스를 돌파한다. 피격 시 잔기가 줄어들며, 잔기가 모두 소진되면 게임 오버 또는 해당 스테이지 재시작으로 이어진다.

### 설계 원칙

1. 탄막은 어려워도 규칙적이어야 한다.
2. 적 등장 위치와 공격 전조를 명확히 보여 준다.
3. 일반 적과 보스는 같은 탄환/패턴 시스템을 공유한다.
4. 한 스테이지는 5~8분, 보스전은 1.5~2분을 목표로 한다.
5. 치명적 오류를 줄이기 위해 데이터 기반보다 **간단한 코드 기반 웨이브 정의**를 우선하고, 시간이 남으면 외부 데이터화한다.

## 3. 게임 씬 및 상태 설계

### 씬 구성

| 씬 | 역할 | 필수 여부 |
|---|---|---|
| `TitleScene` | 게임 시작, 조작 안내 | 필수 |
| `GameScene` | 스테이지 진행과 전투 | 필수 |
| `ResultScene` | 클리어/실패 결과, 점수 표시 | 필수 |
| `EndingScene` | 최종 클리어 연출 | 권장 |

### GameScene 내부 상태

```text
Ready → Playing → MidBoss → Boss → Clear
                    └──────→ GameOver
```

- `Ready`: 스테이지 이름, 조작법을 1~2초 노출한다.
- `Playing`: 웨이브 스폰과 일반 전투를 진행한다.
- `MidBoss`: 선택 요소. 시간 부족 시 일반 웨이브 강화 구간으로 대체 가능하다.
- `Boss`: 보스 UI와 페이즈 제어를 활성화한다.
- `Clear`: 탄환 정리, 점수 집계, 결과 씬 전환을 처리한다.
- `GameOver`: 입력을 제한하고 재시작/타이틀 이동을 제공한다.

## 4. 오브젝트 및 컴포넌트 설계

### 공통 GameObject

모든 게임 오브젝트는 위치, 활성 상태, 컴포넌트 목록을 가진다. 화면 밖 오브젝트는 즉시 삭제하지 말고 비활성화하거나 풀로 반환한다.

### 권장 컴포넌트

| 컴포넌트 | 적용 대상 | 책임 |
|---|---|---|
| `TransformComponent` | 전체 | 위치, 회전, 크기, 이동 방향 |
| `SpriteRendererComponent` | 전체 | 스프라이트/애니메이션 렌더링 |
| `ColliderComponent` | 플레이어, 적, 탄환, 아이템 | 원/사각형 충돌 판정 |
| `HealthComponent` | 플레이어, 적, 보스 | 체력, 피해, 사망 이벤트 |
| `MovementComponent` | 플레이어, 적, 탄환 | 속도, 경로 이동 |
| `WeaponComponent` | 플레이어, 적, 보스 | 발사 주기, 탄환 생성 |
| `BulletPatternComponent` | 적, 보스 | 확산/원형/나선/조준 발사 |
| `DropComponent` | 적, 보스 | 점수 및 아이템 드롭 |
| `BossPhaseComponent` | 보스만 | 페이즈 전환, 패턴 순환 |

### 충돌 레이어

| 레이어 | 충돌 대상 |
|---|---|
| Player | EnemyBullet, Enemy, Item |
| PlayerBullet | Enemy, Boss |
| Enemy | Player, PlayerBullet |
| EnemyBullet | Player |
| Item | Player |

플레이어의 피격 판정은 스프라이트보다 작게 설정한다. 예: 기체 크기 32×32px이면 히트박스는 반지름 4~6px 원형 판정.

## 5. 플레이어 시스템

### 기본 사양

| 항목 | 사양 |
|---|---|
| 이동 | 방향키 또는 WASD, 8방향 |
| 저속 이동 | Shift 입력 시 이동 속도 40~50% |
| 기본 공격 | Z 또는 Space, 자동 연사 |
| 폭탄 | X, 화면 내 적 탄환 제거 및 큰 피해 |
| 초기 잔기 | 3 |
| 초기 폭탄 | 2 |
| 피격 후 무적 | 1.5~2초 |

### 파워업

- 적 처치 시 낮은 확률로 `PowerItem`을 드롭한다.
- 파워는 0~3단계만 운용한다.
- 단계별로 정면탄 수와 보조 공격 수를 증가시킨다.
- 피격 시 파워를 한 단계 낮추는 기능은 일정이 허용될 때만 구현한다.

### 폭탄

폭탄은 위기 회피 장치이므로 한 달 프로젝트에서 반드시 넣는 것을 권장한다.

- 사용 즉시 적 탄환을 전부 제거한다.
- 보스에게는 최대 체력의 5~8% 또는 고정 피해를 준다.
- 0.5초 정도의 화면 플래시와 원형 이펙트를 사용한다.

## 6. 적·탄환·패턴 시스템

### 적 종류

| 종류 | 역할 | 주요 행동 |
|---|---|---|
| 소형 전투기 | 기본 압박 | 편대 이동 후 직선탄 |
| 포대기 | 공간 제어 | 정지 후 조준탄/부채꼴탄 |
| 폭격기 | 고체력 위협 | 느린 이동, 확산탄 |
| 기뢰/드론 | 회피 변주 | 플레이어 추적 또는 회전 이동 |
| 중형 적 | 미니보스 | 다중 포대, 아이템 보상 |

### 필수 탄환 패턴

| 패턴 | 용도 | 구현 난이도 |
|---|---|---|
| 직선탄 | 기본 적 공격 | 낮음 |
| 조준탄 | 플레이어 위치를 향한 사격 | 낮음 |
| 부채꼴탄 | 넓은 범위 압박 | 낮음 |
| 원형탄 | 보스 기본기 | 낮음 |
| 나선탄 | 보스 연출용 | 중간 |
| 유도탄 | Stage 2 이후 | 중간 |
| 격자/교차탄 | 최종 보스 | 중간 |

### 탄환 생성 인터페이스 예시

```cpp
void FireStraight(Vector2 position, Vector2 direction, float speed);
void FireAimed(Vector2 position, Vector2 target, float speed);
void FireFan(Vector2 position, float baseAngle, int count, float spread, float speed);
void FireCircle(Vector2 position, int count, float speed);
void FireSpiral(Vector2 position, float& angle, int count, float speed);
```

탄환은 적 종류별로 별도 클래스를 늘리기보다 `Bullet` 하나에 속도, 방향, 색상, 스프라이트, 특수 이동 타입(직선/가속/유도)을 넣어 재사용한다.

## 7. 스테이지(Map) 설계

### 공통 맵 구조

`Map`은 배경 레이어와 스테이지 이벤트를 관리한다.

```text
Map
 ├─ BackgroundLayer (원거리 배경)
 ├─ MidLayer        (구름, 파도, 구조물)
 ├─ ForegroundLayer (전경 이펙트)
 ├─ ScrollController
 └─ StageDirector   (시간 기반 웨이브/보스 호출)
```

배경은 최소 2레이어 패럴랙스 스크롤을 적용한다. 동일한 텍스처를 반복하는 방식으로 제작해 아트 리소스 부담을 줄인다.

### Stage 1: 구름 위의 국경지대

- 테마: 낮의 하늘, 구름, 산맥, 소형 비행선
- 목표: 이동, 저속 이동, 기본 탄막 패턴 학습
- 길이: 약 5분

| 구간 | 내용 |
|---|---|
| 0:00~1:00 | 소형 전투기 편대, 직선탄 |
| 1:00~2:30 | 포대기와 부채꼴탄 소개 |
| 2:30~3:30 | 구름 속 매복 편대, 원형탄 소개 |
| 3:30~4:00 | 중간보스: 대형 수송선 |
| 4:00~5:30 | 보스: 구름길의 감시자 |

보스 패턴:

1. 부채꼴탄 + 좌우 포탑 사격
2. 화면 횡단 후 원형탄 투사
3. 나선형 탄막(최종 패턴)

### Stage 2: 폭풍 해역과 침몰 함대

- 테마: 어두운 해상, 폭풍, 침몰 전함
- 목표: 유도탄·공간 제한·복합 탄막 대응
- 길이: 약 6분

| 구간 | 내용 |
|---|---|
| 0:00~1:30 | 해상 전투기와 조준탄 |
| 1:30~3:00 | 전함 포대, 유도 미사일 |
| 3:00~4:00 | 잔해/에너지 장벽을 통한 이동 공간 제한 |
| 4:00~4:30 | 중간보스: 부상 전함 |
| 4:30~6:30 | 보스: 폭풍 해역의 함대 제독 |

보스 패턴:

1. 느린 광역 포격
2. 유도탄과 확산탄의 조합
3. 낙뢰 예고 구역 + 격자형 탄막

### Stage 3: 천공 요새의 심장부

- 테마: 비행 요새 외벽과 코어실, 붉은 경보등
- 목표: 기존 패턴의 종합 회피와 최종전 연출
- 길이: 약 7분

| 구간 | 내용 |
|---|---|
| 0:00~2:00 | 드론 편대, 다방향 포대 |
| 2:00~3:30 | 에너지 장벽과 예측 사격 |
| 3:30~4:30 | 중간보스: 요새 방어 AI |
| 4:30~5:00 | 코어실 진입 연출 |
| 5:00~7:00 | 최종 보스: 천공요새의 지휘 코어 |

최종 보스 패턴:

1. 부채꼴탄 + 원형탄 재조합
2. 유도탄 + 이동 경로 제한
3. 회전하는 코어의 나선탄
4. 최종 스펠: 저속 고밀도 탄막과 회전 안전지대

## 8. 보스 시스템

### 보스 공통 규칙

- 보스는 3페이즈를 기본으로 한다. 최종 보스만 4페이즈까지 허용한다.
- 체력이 페이즈 임계값에 도달하면 기존 탄환을 삭제하고 잠시 무적 연출을 준다.
- 페이즈 시작 시 이름과 패턴명을 표시한다.
- 보스는 화면 밖으로 완전히 벗어나지 않는다.

### BossPhase 예시

```cpp
struct BossPhase {
    float hpThreshold;
    float durationLimit; // 시간제 패턴이 필요할 때만 사용
    std::vector<PatternAction> actions;
};
```

패턴은 `대기 → 이동 → 발사 → 휴지`의 반복으로 구성한다. 공격 중에도 플레이어가 피해를 줄 수 있게 하여 전투 템포를 유지한다.

## 9. UI 및 점수 시스템

### HUD 필수 항목

- 좌측 상단: 잔기, 폭탄, 파워 단계
- 우측 상단: 점수, 하이스코어
- 보스전: 보스 이름, 페이즈 이름, 체력바
- 하단 또는 중앙: 일시정지 안내, 스테이지 시작/클리어 메시지

### 점수 규칙

| 행동 | 점수 예시 |
|---|---:|
| 소형 적 격파 | 100 |
| 중형 적 격파 | 1,000 |
| 보스 페이즈 클리어 | 10,000 |
| 노미스 스테이지 클리어 | 20,000 |
| 폭탄 미사용 보너스 | 10,000 |

점수 저장은 우선 실행 중 유지로 충분하다. 파일 저장은 핵심 게임플레이 완성 후 여유가 있을 때 추가한다.

## 10. 사운드 및 연출

### 필수 사운드

- 플레이어 발사, 적 발사, 피격, 폭발, 아이템 획득, 폭탄, 보스 페이즈 전환
- 스테이지별 BGM 1곡, 보스 BGM 1곡 이상

### 필수 연출

- 적 처치 시 작은 폭발과 점수 팝업
- 보스 등장 시 이름 배너 및 화면 흔들림
- 페이즈 전환 시 탄환 삭제와 짧은 플래시
- 폭탄 사용 시 원형 확산 이펙트
- 최종 보스 격파 시 코어 폭발 및 배경 붕괴

화면 흔들림과 플래시는 강도를 낮게 유지하고, 옵션으로 끌 수 있으면 좋지만 한 달 범위에서는 생략 가능하다.

## 11. 4주 개발 일정

### 1주차 — 플레이 기반 완성

- 플레이어 이동, 저속 이동, 발사, 피격, 잔기, 폭탄
- 적/플레이어 탄환 생성 및 충돌
- 오브젝트 풀 또는 간단한 비활성화 재사용 구조
- 기본 HUD, 일시정지, 게임 오버
- Stage 1 일반 웨이브의 프로토타입

**완료 기준:** 적을 쏘고, 피하고, 피격 및 재시작까지 가능한 1분 분량의 플레이 루프.

### 2주차 — 전투 콘텐츠 확장

- 부채꼴, 원형, 나선, 조준 탄환 패턴
- 보스 체력/페이즈 시스템
- Stage 1 보스와 클리어 흐름 완성
- Stage 2 배경과 일반 적 웨이브 구현
- 사운드의 최소 적용

**완료 기준:** Stage 1을 처음부터 보스 격파까지 완주 가능.

### 3주차 — 3스테이지 제작

- Stage 2 보스와 유도탄/공간 제한 기믹
- Stage 3 맵, 웨이브, 중간보스
- 최종 보스 및 엔딩 연출
- 난이도 조정용 상수/디버그 키 추가

**완료 기준:** 3개 스테이지를 처음부터 끝까지 진행 가능.

### 4주차 — 폴리싱 및 안정화

- 전체 난이도와 탄막 속도 조정
- 충돌, 메모리, 씬 전환, 화면 밖 오브젝트 오류 수정
- UI 가독성, 이펙트, 사운드 보완
- 최소 3회 이상 전 구간 플레이 테스트
- 빌드 및 실행 환경 점검

**완료 기준:** 재시작 없이 일반적인 플레이로 전체 게임을 완료할 수 있는 빌드 확보.

## 12. 우선순위 및 범위 관리

### 반드시 구현 (Must)

- 3개 스테이지, 각 스테이지 보스
- 플레이어 이동/공격/피격/폭탄
- 적 웨이브와 4종 이상 탄막 패턴
- 보스 페이즈 및 체력바
- 게임 오버, 클리어, 재시작
- 충돌 판정과 탄환 화면 밖 정리

### 가능하면 구현 (Should)

- 파워업 3단계
- 중간보스
- 스테이지별 고유 기믹
- 스코어 저장
- 난이도 선택

### 일정 부족 시 제외 (Could)

- 대화 이벤트와 상세 스토리
- 복잡한 애니메이션
- 다수의 플레이어 기체
- 온라인 랭킹
- 정교한 패턴 에디터/외부 데이터 툴

## 13. 테스트 체크리스트

- [ ] 플레이어가 화면 밖으로 이동하지 않는다.
- [ ] 피격 후 무적 시간 동안 연속 피해를 받지 않는다.
- [ ] 폭탄이 적 탄환을 전부 제거한다.
- [ ] 탄환과 적이 화면 밖에서 정상 해제된다.
- [ ] 보스 페이즈 전환 시 이전 페이즈 탄환이 남지 않는다.
- [ ] 씬 재시작 시 적, 탄환, 점수, UI가 중복되지 않는다.
- [ ] Stage 1~3을 순서대로 클리어할 수 있다.
- [ ] 게임 오버 후 타이틀/재시작이 정상 동작한다.
- [ ] 탄막이 프레임 저하 상황에서도 지나치게 빨라지거나 느려지지 않는다(delta time 적용).

## 14. 최종 구현 판단 기준

한 달 프로젝트의 성공 기준은 기능의 양이 아니라, 다음 경험이 끊기지 않는 것이다.

> 시작 → 적과 탄막의 규칙 학습 → 보스 공략 → 클리어 보상 → 다음 스테이지 도전

아트와 추가 모드보다 조작감, 충돌 정확도, 탄막의 가독성, 보스전의 완주 가능성을 우선한다.
