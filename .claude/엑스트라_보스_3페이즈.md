# 엑스트라 보스 3페이즈 구조 (BorderAimedBurst)

## 문서 개요

엑스트라 스테이지 보스(`g_extraBossPhases`, `Client/GameScene.cpp`)의 3페이즈에서 사용하는
`BossPatternType::BorderAimedBurst` 패턴의 구조를 정리한다. 실험용 패턴으로, 화면 테두리를
따라 움직이는 마법진 6개가 쉬지 않고 조준탄을 계속 쏘는 형태다.

관련 파일: `Client/Boss.h`, `Client/Boss.cpp`, `Client/GameScene.cpp`.

## 개념

- 마법진(마커) 6개가 화면 네 귀퉁이를 잇는 테두리 위를 각자 독립적으로 미끄러지듯 이동한다.
- 이동 중에도 멈추지 않고 일정 간격으로 전체 마커가 동시에 조준탄을 발사한다.
- 보스 본체와는 별개로, 순수 렌더링용 장식(마법진 텍스처)만 그려질 뿐 실제 Actor/충돌체는
  없다 — 발사되는 탄환만 충돌 판정을 가진다.
- 3페이즈는 보스 HP 0에서 종료되는 마지막 페이즈이므로 `hpThreshold`가 0으로 설정되어 있다
  (더 이상 전환할 다음 페이즈가 없음).

## 데이터 구조

```cpp
// Boss.h
struct BorderMarker
{
    int32 fromCorner = 0;
    int32 toCorner = 1;
    float segmentTime = 0.f;
    bool aimAtPlayer = false;
};
BorderMarker _borderMarkers[6];
int32 _borderBurstTimerId = -1;
float _borderBurstInterval = 0.3f;
float _borderBulletSpeed = 100.f;
float _borderGlideDuration = 1.5f;
float _borderPauseDuration = 1.0f;
```

`BorderMarker` 6개가 완전히 독립적인 상태 머신이다. 서로의 위치를 참조하지 않고, 각자
자기 `segmentTime`만 흘려보내며 코너→코너 이동을 반복한다.

- `fromCorner`/`toCorner`: 현재 이동 중인 구간의 시작/끝 코너 인덱스 (0~3, `getBorderCornerPos()` 참고).
- `segmentTime`: 이번 구간에 들어선 뒤 흐른 시간. glide 구간과 pause 구간을 합쳐서 잰다.
- `aimAtPlayer`: 이 마커가 쏘는 탄이 플레이어를 조준하는지, 화면 중앙 고정 좌표를 조준하는지.

## 코너 좌표 및 이동 (테두리 그래프 랜덤 워크)

```cpp
Vector Boss::getBorderCornerPos(int32 cornerIndex) const
{
    switch (((cornerIndex % 4) + 4) % 4)
    {
        case 0: return Vector(0.f, 0.f);
        case 1: return Vector((float)GWinSizeX, 0.f);
        case 2: return Vector((float)GWinSizeX, (float)GWinSizeY);
        default: return Vector(0.f, (float)GWinSizeY);
    }
}
```

코너 0→1→2→3→0(시계) 순서로 인접해 있고, 인접한 두 코너는 항상 X축 또는 Y축 좌표 중
**한쪽만** 다르다(예: 0↔1은 X만 다름, 1↔2는 Y만 다름). 그래서 "다음 코너로 이동"이라는
동작 하나가 자연히 X축 이동 또는 Y축 이동 중 하나로 결정되고, 별도로 축을 랜덤 선택하는
로직 없이 `cornerIndex ± 1`만 랜덤으로 골라도 "이동 축이 랜덤"인 것처럼 보인다.

```cpp
void Boss::updateBorderMarkers(float deltaTime)
{
    float segmentDuration = _borderGlideDuration + _borderPauseDuration;
    for (int32 i = 0; i < 6; ++i)
    {
        BorderMarker& m = _borderMarkers[i];
        m.segmentTime += deltaTime;
        if (m.segmentTime >= segmentDuration)
        {
            m.segmentTime -= segmentDuration;
            m.fromCorner = m.toCorner;
            int32 dir = (rand() % 2 == 0) ? 1 : -1;
            m.toCorner = m.fromCorner + dir;   // 코너 도착마다 CW/CCW를 독립적으로 다시 뽑는다
        }
    }
}

Vector Boss::getBorderMarkerPos(int32 markerIndex) const
{
    const BorderMarker& m = _borderMarkers[markerIndex];
    Vector from = getBorderCornerPos(m.fromCorner);
    Vector to = getBorderCornerPos(m.toCorner);
    float t = (m.segmentTime < _borderGlideDuration) ? (m.segmentTime / _borderGlideDuration) : 1.f;
    return from + (to - from) * t;
}
```

한 구간(`segmentDuration`)은 "미끄러지듯 이동(glide)" + "제자리에서 대기(pause)"로 나뉜다.
`getBorderMarkerPos()`는 `segmentTime`이 `_borderGlideDuration`을 넘기면 `t`를 1로 고정하므로,
glide 구간에서는 선형보간으로 코너 사이를 이동하고, 그 뒤 남은 시간(pause 구간) 동안은 도착
코너에 멈춰 있다가 `updateBorderMarkers()`가 다음 코너를 다시 뽑으면서 구간이 갱신된다.

## 마커 배치 (그룹/조준 대상/시작 오프셋)

```cpp
void Boss::initBorderMarkers()
{
    for (int32 i = 0; i < 6; ++i)
    {
        bool groupB = (i >= 3);
        int32 startCorner = groupB ? 2 : 0;    // 그룹A=(0,0), 그룹B=대각선 반대 코너
        int32 dir = (rand() % 2 == 0) ? 1 : -1;

        _borderMarkers[i].fromCorner = startCorner;
        _borderMarkers[i].toCorner = startCorner + dir;
        _borderMarkers[i].segmentTime = (i == 2 || i == 5) ? 0.2f : 0.f;
        _borderMarkers[i].aimAtPlayer = (i == 0 || i == 3);
    }
}
```

| 마커(1-based) | 인덱스 | 그룹 | 시작 코너 | 조준 대상 | 탄 색 | 시작 오프셋 |
|---|---|---|---|---|---|---|
| 1 | 0 | A | (0,0) | 플레이어 | OrbRed | 없음 |
| 2 | 1 | A | (0,0) | 화면 중앙 (300,400) | OrbBlue | 없음 |
| 3 | 2 | A | (0,0) | 화면 중앙 (300,400) | OrbBlue | +0.2초 |
| 4 | 3 | B | 대각선 반대 코너 | 플레이어 | OrbRed | 없음 |
| 5 | 4 | B | 대각선 반대 코너 | 화면 중앙 (300,400) | OrbBlue | 없음 |
| 6 | 5 | B | 대각선 반대 코너 | 화면 중앙 (300,400) | OrbBlue | +0.2초 |

3번/6번만 `segmentTime`을 0.2초 앞당긴 채로 시작한다. 이건 서로의 경로를 실제로 따라가며
재생하는 "trailing" 구현이 아니라, 각자 독립적인 시계가 살짝 어긋난 것뿐이다 — 그래도 초반
잠깐은 리더(1번/4번 그룹 내 첫 마커)와 살짝 어긋나 보이는 시각 효과를 낸다. 이후에는 각
마커가 코너 도착마다 독립적으로 CW/CCW를 다시 뽑기 때문에 시간이 지날수록 완전히
비동기화된다.

## 발사

```cpp
void Boss::shootBorderAimedBurst()
{
    const Vector fixedTarget(300.f, 400.f);
    Player* player = scene->GetPlayer();

    for (int32 i = 0; i < 6; ++i)
    {
        Vector pos = getBorderMarkerPos(i);
        bool aimAtPlayer = _borderMarkers[i].aimAtPlayer;
        Vector target = (aimAtPlayer && player != nullptr) ? player->GetPos() : fixedTarget;
        wstring textureKey = aimAtPlayer ? L"OrbRed" : L"OrbBlue";

        Vector dir = target - pos;
        dir.Normalize();
        scene->CreateBullet(pos, BulletType::Enemy, dir, _borderBulletSpeed, /*...*/);
    }
}
```

매 틱마다 마커 6개 전부가 **동시에** 한 발씩, 그 순간의 자기 위치에서 조준선을 계산해
발사한다(유도탄이 아니라 발사 시점 방향으로 직진하는 일반 조준탄).

## 지속 발사 타이머 배선

Spiral/Cross/ConvergingBurst와 동일한 아키텍처를 재사용한다: 해당 페이즈의 타임라인에
`BorderAimedBurst`가 포함되어 있으면(`ContainsBorderAimedBurst()`), `Boss::Init()`과
`transitionToNextPhase()` 양쪽에서 마커를 초기화하고 반복 타이머를 건다.

```cpp
if (ContainsBorderAimedBurst(_phases[_curPhaseIndex].timeline))
{
    initBorderMarkers();
    _borderBurstTimerId = TimeManager::GetInstance().AddTimer(
        [this]() { shootBorderAimedBurst(); }, _borderBurstInterval, true);
}
```

- `Boss::Update()`에서 `_borderBurstTimerId != -1`인 동안 매 프레임 `updateBorderMarkers(deltaTime)`를 호출해 위치를 갱신한다.
- 페이즈 타임라인의 일반 dispatch 루프는 `BorderAimedBurst`를 건너뛴다 (지속 타이머가 대신 처리하므로).
- `Boss::Destroy()`에서 `TimeManager::GetInstance().Remove(_borderBurstTimerId)`로 정리한다.

## 렌더링 (장식용, 충돌 없음)

`Boss::Render()`에서 `_decorPhaseIndex` 마법진 블록 다음, `Super::Render(hdc)` 이전에
마커 6개 위치에 `MagicCircle` 텍스처를 그린다. 이 마법진들은 순수 시각 요소일 뿐 Actor로
존재하지 않으며 충돌 판정도 없다 — 위험한 건 여기서 나가는 탄환뿐이다.

```cpp
if (_borderBurstTimerId != -1)
{
    Texture* magicCircle = ResourceManager::GetInstance().GetTexture(L"MagicCircle");
    for (int32 i = 0; i < 6; ++i)
        magicCircle->Render(hdc, getBorderMarkerPos(i));
}
```

## 최종 튜닝 값

| 파라미터 | 값 | 비고 |
|---|---|---|
| `_borderBurstInterval` | 0.3초 | 발사 간격 (0.1 → 0.3까지 여러 차례 조정) |
| `_borderBulletSpeed` | 100 | 탄 속도 (180 → 150 → 100) |
| `_borderGlideDuration` | 1.5초 | 코너 간 이동 시간 (1.0 → 1.5, "느리게") |
| `_borderPauseDuration` | 1.0초 | 도착 후 대기 시간 (변경 없음) |

이 값들은 `Init()` 파라미터로 노출되어 있지 않고 `Boss.h`의 멤버 기본값으로 직접
박혀 있다 — 즉 **엑스트라 보스 3페이즈 전용 수치**이며, 다른 보스가 이 패턴을 재사용하면
같은 값을 그대로 물려받는다(현재는 엑스트라 보스만 사용).

## GameScene 배선

```cpp
// Client/GameScene.cpp
static const vector<BossPhase> g_extraBossPhases =
{
    { {...1페이즈 타임라인...}, 6.0f, 4500 },
    { { { 0.f, BossPatternType::ConvergingBurst } }, 1.0f, 4000 },
    { { { 0.f, BossPatternType::BorderAimedBurst } }, 1.0f, 0 },   // 3페이즈
};
```

`GameSceneState::ExtraBoss` 케이스에서 `boss->Init(..., g_extraBossPhases, 5000, ...)`로
생성한다. `maxHp=5000` 기준 `hpThreshold`가 4500→4000→0 순으로 내려가며 1→2→3페이즈로
전환되고, 3페이즈는 `hpThreshold=0`이므로 HP가 0이 될 때(보스 사망)까지 유지된다.
