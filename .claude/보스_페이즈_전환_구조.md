# 보스 페이즈 전환 구조

## 문서 개요

`Boss`(`Client/Boss.h`, `Client/Boss.cpp`)가 한 페이즈의 타임라인을 재생하다가 HP 임계값
아래로 떨어지면 다음 페이즈로 넘어가는 전체 흐름을 정리한다. 페이즈 데이터 정의는
`Client/GameScene.cpp`의 `g_stage1BossPhases` 등 `vector<BossPhase>` 상수들을 예시로 쓴다.

관련 파일: `Client/Boss.h`, `Client/Boss.cpp`, `Client/GameScene.cpp`.

## 데이터 구조

```cpp
// Boss.h
struct TimelineStep
{
    float time;
    BossPatternType pattern;
};

struct BossPhase
{
    vector<TimelineStep> timeline;
    float cycleLength;
    int32 hpThreshold;
};
```

- 한 `BossPhase`는 `cycleLength`초짜리 타임라인을 계속 반복 재생한다. `timeline`의 각
  `TimelineStep`은 "사이클 시작 후 `time`초가 지나면 `pattern`을 한 번 쏜다"는 의미다.
  같은 `time`을 여러 스텝이 공유해도 되고(동시 발사), 한 사이클 안에 같은 패턴이 여러 번
  나와도 된다(`g_stage2BossPhases`의 2페이즈처럼 0.3초 간격으로 8번).
- `hpThreshold`는 **절대 HP 값**이다. 현재 페이즈에서 `_hp`가 이 값 이하로 떨어지면 다음
  페이즈로 전환된다. 예: `g_extraBossPhases`의 1페이즈는 `hpThreshold = 4500`, maxHp가
  5000이므로 10%(500)만 깎여도 전환된다.
- 마지막 페이즈의 `hpThreshold`는 관례상 `0`(더 전환할 다음 페이즈가 없으므로 사실상
  "죽을 때까지 유지"라는 의미).
- `Boss::Init()`에 이 배열을 그대로 `vector<BossPhase> phases`로 넘긴다
  (`GameScene.cpp`의 `boss->Init(..., g_stage1BossPhases, ...)`).

```cpp
// GameScene.cpp
static const vector<BossPhase> g_stage1BossPhases =
{
    { { { 0.f, BossPatternType::Fan } },    1.0f, 100 },
    { { { 0.f, BossPatternType::Circle } }, 1.0f, 40 },
    { { { 0.f, BossPatternType::Spiral } }, 1.0f, 0 },
};
```

## 타임라인 재생 (`Boss::Update`)

```cpp
// Boss.cpp, Update() 안
_phaseElapsedTime += deltaTime;
const vector<TimelineStep>& timeline = _phases[_curPhaseIndex].timeline;
while (_timelineIndex < (int32)timeline.size() && timeline[_timelineIndex].time <= _phaseElapsedTime)
{
    if (/* Spiral/Cross/ConvergingBurst/BorderAimedBurst/Leavatein/Kagome/LoveMaze/StarbowBreak가 아니면 */)
    {
        shootBullet(timeline[_timelineIndex].pattern);
    }
    _timelineIndex++;
}
if (_phaseElapsedTime >= _phases[_curPhaseIndex].cycleLength)
{
    _phaseElapsedTime = 0.f;
    _timelineIndex = 0;   // 사이클 리셋 -> 처음부터 반복
}
```

- `_phaseElapsedTime`/`_timelineIndex`가 "현재 사이클 안에서 어디까지 재생했는지"를 추적하는
  전부다. `while`이 한 프레임에 여러 스텝을 한꺼번에 소화할 수 있어서(같은 `time`을 공유하는
  스텝들, 또는 프레임 드랍으로 여러 스텝을 건너뛰게 된 경우) 스텝을 놓치지 않는다.
- 예외 패턴 목록(Spiral/Cross/ConvergingBurst/BorderAimedBurst/Leavatein/Kagome/LoveMaze/
  StarbowBreak)은 `shootBullet()`을 거치지 않는다. 이들은 "한 번 쏘고 끝"이 아니라 페이즈
  내내 독립된 `TimeManager` 타이머(또는 자체 상태 머신)로 계속 진행되는 연속 패턴이라,
  타임라인에는 그냥 "이 페이즈에 이 패턴이 포함되어 있다"는 표시로만 등장한다(보통
  `{ 0.f, Pattern }` 한 줄). 실제 시작은 `Init()`/`transitionToNextPhase()`에서
  `ContainsXxx(timeline)` 체크로 타이머를 걸 때 일어난다(아래 "연속 패턴" 절 참고).

## HP 임계값 → 전환 트리거 (`Boss::OnEnter`)

```cpp
// Boss.cpp, OnEnter() 안 (플레이어 탄에 맞았을 때)
_hp -= 1;
bullet->Destroy();

if (_curPhaseIndex < (int32)_phases.size() - 1 && _hp <= _phases[_curPhaseIndex].hpThreshold)
{
    transitionToNextPhase();
}

if (_hp <= 0)
{
    Destroy();
    ...
}
```

- 전환 체크는 **피격 시점**에만 일어난다(매 프레임이 아님) — 총알 한 발이 HP를 깎을 때마다
  현재 페이즈의 `hpThreshold`와 비교한다.
- 마지막 페이즈(`_curPhaseIndex == _phases.size() - 1`)에서는 전환하지 않고 그대로 죽을 때까지
  진행한다.
- `_hp <= 0`으로 죽는 것과 페이즈 전환은 같은 피격 이벤트 안에서 순차적으로 체크되므로,
  이론상 한 방에 hpThreshold도 넘고 0 이하로도 떨어지면 `transitionToNextPhase()`가 먼저
  실행된 뒤 곧바로 `Destroy()`가 실행된다.

## 페이즈 전환 처리 (`Boss::transitionToNextPhase`)

```cpp
void Boss::transitionToNextPhase()
{
    Game::GetInstance().GetScene()->ClearEnemyBullets();   // 1. 기존 탄 삭제
    // (5페이즈였다면 분신 정리)
    Game::GetInstance().GetScene()->CreateEffect(GetPos()); // 2. 연출(이펙트로 대체)

    _curPhaseIndex++;
    _phaseElapsedTime = 0.f;
    _timelineIndex = 0;                                     // 3. 새 타임라인 처음부터

    // 4. 연속 패턴 타이머 재설정 (이전 페이즈 것 Remove -> 새 페이즈에 있으면 다시 AddTimer)
    // 5. 스펠카드형 패턴(Kagome/LoveMaze/StarbowBreak) stop -> 새 페이즈에 있으면 start
}
```

전환은 클래스 헤더 주석 그대로 **"기존 탄 삭제 → 연출 → 다음 페이즈로 전환"** 3단계다.

1. **기존 탄 삭제**: `ClearEnemyBullets()`로 화면의 적탄을 전부 지운다. 5페이즈(분신 소환
   페이즈, `_illusionPhaseIndex`)를 벗어나는 경우엔 `ClearBossIllusions()`로 분신도 같이
   정리한다 — 본체가 죽었을 때(`Destroy()`)와 동일한 정리를 페이즈 경계에서도 해줘야 하기
   때문.
2. **연출**: 현재는 `CreateEffect()` 하나로 대체되어 있다(주석에 "Day4는 뼈대만 있으면 됨"이라
   명시 — 나중에 진짜 연출로 교체될 여지가 있는 자리).
3. **다음 페이즈로 전환**: `_curPhaseIndex++` 하고 `_phaseElapsedTime`/`_timelineIndex`를
   0으로 리셋해 새 타임라인을 처음부터 재생한다.

### 연속 패턴(Spiral/Cross/ConvergingBurst/BorderAimedBurst) 타이머 재설정

Spiral·Cross·ConvergingBurst·BorderAimedBurst는 "페이즈 내내 일정 간격으로 계속 쏘는" 연속
발사라 `TimeManager` 반복 타이머로 구현되어 있다. 페이즈가 바뀔 때마다 다음 패턴을 **반복**한다:

```cpp
TimeManager::GetInstance().Remove(_spiralShootTimerId);
if (ContainsSpiral(_phases[_curPhaseIndex].timeline))
{
    _spiralShootTimerId = TimeManager::GetInstance().AddTimer([this]() { shootSpiralBullet(); }, _spiralInterval, true);
}
```

즉 **이전 페이즈의 타이머를 무조건 Remove하고, 새 페이즈에 해당 패턴이 있을 때만 다시 건다.**
이 패턴이 `Boss::Init()`(최초 페이즈 시작)과 `transitionToNextPhase()`(이후 모든 전환) 양쪽에
거의 동일하게 반복된다 — 새 연속 패턴을 추가할 때는 두 곳 모두에 같은 짝(Remove + 조건부
AddTimer)을 넣어야 한다는 뜻.

`BorderAimedBurst`는 타이머 Remove 후 `_borderBurstTimerId`를 `-1`로 직접 리셋해주는데,
이는 `Remove()`가 ID를 값으로 받아서 멤버 변수 자체는 안 건드리기 때문 — 이 리셋을 빼먹으면
이전 페이즈에서 켜졌던 마법진 렌더링/갱신 조건(`_borderBurstTimerId != -1`)이 새 페이즈에서도
계속 켜진 채로 남는다.

### 스펠카드형 패턴(Leavatein/Kagome/LoveMaze/StarbowBreak) 시작/정지

이 넷은 반복 타이머 하나로 표현하기엔 상태가 복잡해서(예: 레바테인의 Sweep/Pause/
Reposition/Slide 4단계, 카고메의 격자탄 웨이브+큰 탄 리듬 두 상태머신) 전용
start/stop 함수 쌍으로 관리된다. `transitionToNextPhase()`는 이전 페이즈용을 무조건
`stop`한 뒤, 새 페이즈에 해당 패턴이 있으면 `start`한다:

```cpp
stopKagomeSpellcard();
if (ContainsKagome(_phases[_curPhaseIndex].timeline)) { startKagomeSpellcard(); }

stopLoveMazeSpellcard();
if (ContainsLoveMaze(_phases[_curPhaseIndex].timeline)) { startLoveMazeSpellcard(); }

stopStarbowBreak();
if (ContainsStarbowBreak(_phases[_curPhaseIndex].timeline)) { startStarbowBreak(); }
```

Leavatein은 `_leavateinActive` 플래그 + 레이저 액터(`_leavateinLaser`) 정리까지 겸해서 직접
인라인으로 처리된다(별도 `stopLeavatein()` 없이 `transitionToNextPhase()` 안에 풀어져 있음).

### 5페이즈(분신 소환) 특수 처리

`_illusionPhaseIndex`로 지정된 페이즈에 **들어갈 때** `spawnIllusionClones()`로 분신 3체를
스폰한다. 벗어날 때 정리하는 로직은 위 1단계("기존 탄 삭제")에 이미 포함되어 있다.

## 흐름 요약

```
플레이어 탄이 보스에 명중 (OnEnter)
        │
        ▼
   _hp -= 1
        │
        ▼
 hp <= 현재 페이즈 hpThreshold? ──아니오──▶ (같은 페이즈 계속, Update의 타임라인 루프가 진행)
        │ 예 (그리고 마지막 페이즈가 아님)
        ▼
 transitionToNextPhase()
   1. ClearEnemyBullets() (+ 5페이즈였다면 분신 정리)
   2. CreateEffect() (연출)
   3. _curPhaseIndex++, _phaseElapsedTime/_timelineIndex = 0
   4. 연속 패턴 타이머 Remove → 새 페이즈에 있으면 재등록
   5. 스펠카드형 stop → 새 페이즈에 있으면 start
   6. (5페이즈 진입이면 spawnIllusionClones())
        │
        ▼
 새 페이즈 타임라인이 처음부터 반복 재생 (Update의 while 루프)
```

## 새 페이즈/연속 패턴을 추가할 때 체크리스트

1. `BossPatternType`에 새 enum 값 추가.
2. 한 번 쏘고 끝나는 단발성 패턴이면 `shootBullet()`의 `switch`에 케이스 추가 — 이게 끝.
3. 페이즈 내내 계속되는 연속 패턴이면:
   - `Update()`의 예외 패턴 목록(스킵 조건)에 추가.
   - `ContainsXxx()` 헬퍼 작성.
   - `Boss::Init()`과 `transitionToNextPhase()` 양쪽에 `Remove` + 조건부 `AddTimer`(또는
     `stopXxx()`/`startXxx()` 쌍)를 동일하게 추가.
   - `Boss::Destroy()`에도 해당 타이머/상태 정리를 추가해야 보스가 죽을 때 누수/잔여 상태가
     안 남는다.
4. `GameScene.cpp`에 새 `BossPhase` 배열(또는 기존 배열에 페이즈 추가)을 만들고
   `hpThreshold`를 정한다.
